# Integration status

Nicrron line explanations and local PRISM tracing were verified with a real application call on October 10, 2026 using synthetic RFQ data and `openai/gpt-4.1-mini`. PRISM returned `live_connected: true` and `overall: connected`. Production PRISM credentials have not been configured. Demo data stays explicitly labeled even when the explanatory text is generated by a real model.

## Nicrron

The server adapter uses the documented OpenAI-compatible `POST https://api.nicrron.ai/v1/chat/completions` endpoint. `NICRRON_MODEL` is configurable; `openai/gpt-4.1-mini` appears in the published model catalog and was tested. Explanation calls use a 1,400-token output cap, zero temperature, and explicitly disable the gateway cache. A 30-second timeout and strict schema/source checks protect state. Keys stay in server environment variables. A configured key alone never displays Connected; a successful explanation or synthetic connection check does.

The Match tab’s **Why this match?** card generates an explanation on demand. It covers the selected catalog match, selling price versus a comparable benchmark, evidence limitations, and up to three nearby alternatives. The provider receives an allowlisted set of derived facts; customer/contact fields, the raw request, and document contents are omitted. The response must match a strict schema, cite known facts from the correct section, retain only supplied alternative SKUs, and introduce no numeric tokens absent from its citations. This is a bounded source check, not proof of semantic correctness; users still review the exact facts and make approval decisions.

Explanations are persisted within the browser workspace and reused without a provider call while the RFQ revision, facts, prompt version, and model remain unchanged. Changes invalidate them; responses completing after edits are discarded. Generation never mutates quote prices, evidence, or approval state. Provider/schema failures are explicit and never replaced with fabricated AI output. A persisted global quota defaults to 100 explanation/connection calls per UTC day (`NICRRON_DAILY_REQUEST_LIMIT`, maximum 1,000), with 20 per workspace. Failed calls count toward the allowance. Public visitors cannot reset the global counter by clearing cookies.

Live extraction is implemented but unverified. Clarification drafting and interpretation in the current UI use explicit demo rules, not a verified live AI drafting integration. Do not present the latter as complete.

Sources checked October 10, 2026: [Nicrron quickstart](https://nicrron.ai/docs/quickstart), [model catalog](https://nicrron.ai/docs/models).

## Block Convey PRISM

The shared Nicrron completion adapter awaits one HTTP trace for each actual provider invocation, including explanation, extraction and connection-check calls. Traces use `X-PRISMtrace-Key`, the actual model, measured provider latency, reported token counts when available, and sanitized provider error codes. PRISM outages do not discard the model response. Cached explanations and deterministic demo parsing make no model call and generate no model trace. The old extra synthetic extraction summary has been removed to avoid double counting.

RFQ sessions are hashed together with the signed browser workspace scope; identical RFQ IDs in separate workspaces remain separate. Agent identity is stable (`quoteguard-estimator`). Connection checks are labeled synthetic. An actual model invocation on sample RFQ facts is labeled as a live call with sample data, rather than fabricated model activity. No agent tools, retrievers or graphs are present in the current call path; no such events are invented.

The supplied credential passed `POST /api/setup-doctor/handshake` with HTTP 200. In a fresh, isolated localhost app and SQLite database, the real `POST /api/rfqs/RFQ-1042/lines/line-1/explanation` handler generated and saved a validated Nicrron explanation. The subsequent authenticated doctor check reported one live application trace, one assembled trajectory and one analysed live trace. See [verification evidence](prism-verification.json). This confirms tracing, not quote approval or benchmark accuracy.

Prompt/response content is omitted by default (`PRISMTRACE_CAPTURE_CONTENT=false`). Explicit opt-in sends bounded content with configured provider credentials redacted. The isolated verification opted in only for built-in synthetic data and was stopped afterward. Metadata-only traces are for operational visibility; any scores on omitted-content placeholders are not content-quality evidence. Follow the [local setup notes](prism-setup.md) before enabling content capture or a hosted environment. The code records provider errors; downstream explanation/source-validation failures are still application errors, not separate PRISM events.

PRISM evaluation, Knowledge Base grounding, and inline prevention with Nicrron remain **Unavailable**. The reviewed public documentation did not establish the necessary callable contracts or support for chaining Nicrron through PRISM's provider proxy. No endpoints or SDKs were invented. The local regex input check and deterministic readiness evaluator are labeled as application checks, never as PRISM results.

Setting `REQUIRE_PRISM_EVALUATION=true`, or selecting live mode, blocks final approval until a current passed evaluation can be supplied by a future verified adapter. There is no browser bypass for this policy. Keep demo mode enabled for the complete prototype walkthrough.
